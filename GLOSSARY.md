# Guito UI glossary

Domain vocabulary, not deployment or approval history. Read [domain guidance](docs/agents/domain.md) for contract prerequisites.

- **Expense occurrence (`bookingDate`)** — purchase instant, distinct from creation/update audit timestamps. Editable Date/Time use Europe/Lisbon regardless of browser timezone. Capture now once for new forms/favorite taps; date-only voice/bank prefills combine their day with captured Lisbon time. Preserve known offset instants/seconds until Date/Time edits. Reject DST gaps and unresolved folds; historical-import midnight is not a new-expense default ([ADR 0014](docs/adr/0014-expense-occurrence-lisbon.md)). `occurredAt` is not the wire property.
- **Expense ID** — durable numeric identity (API Int32); the current adapter accepts positive safe integers and digit-only legacy strings. Missing latest identity stays null and rows track by object. Neither `storedOrder` nor array position is identity. An opaque legacy create acknowledgement means success with null identity, not a failed write to retry. Bank/category identities are separate contracts.
- **Exact amount** — one normalized invariant decimal string across Expense HTTP mapping, form state, prefills and POST. Signed and zero values are valid; preserve sign, normalize leading plus/negative zero, enforce .NET decimal coefficient/scale bounds without Number conversion or two-decimal transport rounding. Numeric compatibility preserves only the already-represented value, never upstream lost digits. Bank `amountExact` is consumed once at its boundary, not retained as a second internal amount. Current master display formatting uses Number conversion; exact transport does not prove exact rendered cents.
- **Unknown legacy data** — explicit null `bookingDate` never falls back to legacy/audit fields; missing dates group as Unknown date, missing amounts display an em dash. Legacy `date`/numeric amounts are normalized only at the HTTP boundary. Group by Lisbon day while retaining server timestamp order, not ID/order-of-import.
- **Pending bank transaction (baseline UI)** — imported bank row displayed by the Bank page with sync and Accept-to-create-prefill. Accept alone is not matching or atomic create-and-link. Reconciliation's needs-review/matched/ignored states are separate from bank booking status; an AI category is not a match, and no suggestion is not proof an expense is absent. The newer inbox is a separate unmerged change; see the [domain guide](docs/agents/domain.md).
